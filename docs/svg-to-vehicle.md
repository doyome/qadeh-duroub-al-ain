# برومبت: تحويل سيارة من SVG إلى مركبة داخل «قادح — دروب العين»

انسخ كل ما تحت الخط وألصقه في Claude Code **مع ملف الـ SVG في نفس الرسالة**.

---

## المهمة

عندك ملف SVG لسيارة (منظر جانبي). حوّله إلى مركبة قابلة للعب داخل لعبة `قادح — دروب العين`
الموجودة في هذا المستودع، بنفس أسلوب المركبات الحالية بالضبط.

**قبل ما تفتح ملف الـ SVG:** اقرأ `index.html` وادرس فعليًا الدالة `suv(c,p)` وتعريفات
`fatak` و`rubaa` و`y60` و`lc` في مصفوفة `VEH`. الوصف تحت مطابق للكود، بس تأكد بنفسك.

---

## ١) كيف تُرسم المركبات هنا (الحقائق)

المحرّك **Canvas 2D فقط** — لا Three.js ولا WebGL ولا أي مكتبة رسم. ما فيه صور ولا
sprites: كل مركبة **رسم متجهي إجرائي** مكتوب بأوامر مسارات.

### نظام الإحداثيات داخل `draw(c, v)`

الدالة تُستدعى وهي أصلاً داخل `save/translate/rotate/restore` في `drawCar`، فلا تنقل ولا
تدوّر جسم المركبة بنفسك:

```
المحور:      +x = للأمام (يمين الشاشة)   |   +y = لتحت
نقطة الأصل:  مركز ثقل الهيكل
y = +45   ← خط ملامسة الأرض وقت الوقوف المستوي  (ly=-6 + rest=22 + r=29)
y = +10   ← أسفل الهيكل (sill) → خلوص أرضي ≈ ٣٥ بكسل
y = -22..-30 ← خط الحزام (أسفل الزجاج)
y = -52..-62 ← السقف
±L       ← نصف طول المركبة: 72 (ربع) … 110 (طويل)
```

### المقياس — لا «تصحّحه»

`PPM = 34` بكسل لكل متر. لكن الرسم **مبالغ فيه عمدًا بأسلوب أركيد**: الطول أكبر من الواقعي
بـ١٢٪ تقريبًا، والارتفاع والعجلات أكبر بكثير. لا ترجّع النسب إلى الواقعية —
بتطلع المركبة غريبة جنب البقية، وبتكسر الفيزياء لأن نصف قطر العجلة `r` معامل فيزيائي.

### قاعدة المسار الواحد (الأهم)

جسم المركبة **مسار واحد مغلق** يُملأ بتدرّج رأسي واحد، وقواعد العجلات **محفورة داخل نفس
المسار**:

```js
c.beginPath(); c.moveTo(-L, sill);
for (كل نقطة في sil) c.lineTo(x, y);      // الظلّية العلوية: من المؤخرة إلى الأنف
c.lineTo(L, sill);
c.lineTo(wf+arch, sill); c.arc(wf, sill, arch, 0, Math.PI, true);   // قاعدة أمامية
c.lineTo(wr+arch, sill); c.arc(wr, sill, arch, 0, Math.PI, true);   // قاعدة خلفية
c.closePath();
```

`drawCar` يرسم **العجلات أولاً ثم الهيكل فوقها**. الحفرتان هما اللي تخلّي الإطار يبان.
لو ملأت الهيكل كمستطيل صلب بدون حفر → تختفي الإطارات تمامًا.

## ٢) الصيغة المطلوبة للمخرَج

**لا تكتب دالة رسم جديدة من الصفر إن كانت المركبة دفع رباعي.** عبّر عنها كوسائط لـ `suv(c,p)`:

| الوسيط | المعنى |
|---|---|
| `L` | نصف الطول |
| `wf`, `wr` | مركز العجلة الأمامية/الخلفية على x |
| `arch` | نصف قطر حفرة قاعدة العجلة (٣٣–٣٥) |
| `sill` | أسفل الهيكل (١٠) |
| `roofY` | خط السقف |
| `sil[]` | نقاط الظلّية العلوية `[x,y]` من المؤخرة إلى الأنف |
| `gh[4]` | مضلّع الزجاج: `[خلفي‑أسفل, خلفي‑أعلى, أمامي‑أعلى, أمامي‑أسفل]` |
| `pillars[]` | مواضع x للأعمدة بين النوافذ |
| `doors[]` | مواضع x لخطوط الأبواب (المقبض يُرسم تلقائيًا خلف كل خط بـ١٤ بكسل) |
| `c1`, `c2` | لون الطلاء أعلى/أسفل (hex صريح) |
| `lights` | `'square'` أو `'round'` أو `'chrome'` |
| `chrome`, `dark`, `flare` | ألوان الكروم والصدامات والرفارف (اختيارية) |
| `rack`+`rackB`+`rackF`, `bar`, `snorkel`, `spare` | رف السقف، بار الكشافات، السنوركل، الإطار الاحتياطي |
| `driver` | موضع x لراس السائق (تُرسم بـ`head()`) |

مثال حقيقي من الكود (الفتك) — هذا هو حجم المخرَج المتوقع:

```js
draw:function(c){suv(c,{L:95,wf:58,wr:-58,arch:35,sill:10,roofY:-62,
  sil:[[-95,-26],[-93,-56],[-74,-62],[24,-62],[36,-28],[86,-26],[95,-18]],
  gh:[[-70,-30],[-70,-56],[20,-56],[32,-30]],pillars:[-34,2],doors:[-38,6,50],
  c1:'#2E4470',c2:'#1A2740',lights:'square',snorkel:36,rack:1,rackB:-68,rackF:18,bar:1,
  flare:'#171B21',driver:-6});}
```

**ميزانية الحجم:** دالة رسم المركبة ≈ ١٠–٢٥ سطر. لو طلع عندك ٢٠٠ سطر من بيانات مسارات
مستوردة من الـ SVG فأنت غلطان — بسّط إلى ظلّية + طبقات تفاصيل.

## ٣) الفيزياء ليست اختيارية

هذي الحقول **معاملات فيزياء وليست رسم**، ولازم تطابق الرسم:

```js
mass, power, maxSpeed, grip, air, fuel,     // الإحساس والأداء
wf, wr, r, rest, sMin, sMax, kM, cM,        // هندسة العجلات والتعليق
pts: suvPts(L, roofY, ghF, ghB),            // نقاط التصادم
thumb                                        // تكبير مصغّرة الكراج
```

- `pts` = نقطتا مصدّ عند `y:12` + ثلاث نقاط سقف عليها `k:1`.
  ملامسة نقطة `k` تنهي الجولة **فقط** إذا كانت زاوية المركبة > ١.٠٥ راديان (انقلاب حقيقي)؛
  غير كذا تُحسب خبطة سقف تكلّف السرعة والمضاعف.
- لو عجلات الرسم ما وقعت على `wf/wr/r` → المركبة تطفو فوق الأرض أو يكشط بطنها ويكتم سرعتها.
- خلّي `mass/power/maxSpeed/price` منسجمة مع تدرّج المركبات الموجود (السكوتر ← الدبابة).

## ٤) ممنوعات صارمة

1. **التحويل خطوة لمرة وحدة خارج اللعبة.** ملف الـ SVG لا يُشحن، ولا يُقرأ وقت التشغيل،
   ولا يُضمَّن كـ data-URI، ولا يُحلَّل بأي كود داخل اللعبة. المخرَج كود مسارات فقط.
2. **صفر مكتبات وصفر طلبات شبكة جديدة.** اللعبة ملف `index.html` واحد مستقل؛ الطلبات
   الخارجية الوحيدة المسموحة هي رابطا خطوط Google الموجودان أصلاً. لا تضيف خطوة بناء
   ولا `package.json` للعبة نفسها.
3. **لا `<img>` ولا `Image()` ولا `drawImage` ولا sprite sheets.** ولا WebGL.
4. `Path2D` أصلية في المتصفح ومسموحة **فقط** لزخرفة صغيرة (نقشة شبك، شعار) —
   وممنوعة لظلّية الهيكل، لأن الهيكل لازم يبقى المسار الواحد المُعامَل بوسائط.
5. كل `c.save()` يقابله `c.restore()`. لا تستخدم المتغيّر العام `ctx` — استخدم `c` الممرَّر.
6. ألوان hex صريحة داخل الكانفس، بدون متغيّرات CSS.
7. لا تلمس `physics()` ولا مولّد التضاريس عشان تخلّي سيارتك تشتغل.

## ٥) التحقق مطلوب قبل ما تقول «خلصت»

المستودع فيه أدوات فحص headless تشغّل اللعبة في Node بدون متصفح. شغّلها كلها:

```bash
node tools/physics.js   # ١١٥ فحص: بدون NaN، تتحرك، تستقر مستوية، التطويرات تؤثر
node tools/render.js    # كل مسارات الرسم تنفّذ بدون استثناء (٦ مراحل × كل المركبات + المصغّرات)
node tools/air.js       # المركبة تطير فعلاً: زمن هواء وارتفاع وعدد قفزات
node tools/pilot.js     # طيّار آلي يقيس المسافة عبر المراحل الست
```

الشروط: `ALL CHECKS PASSED` و`ALL RENDER PATHS OK` و`ALL AIR CHECKS PASSED`،
و`tools/pilot.js` يعطي مسافة للمركبة الجديدة قريبة من مركبة مماثلة في السعر.
لو `pilot.js` طلّع لها مسافة أقل بكثير → في خلل في الخلوص الأرضي أو نقاط التصادم.

**نبّهني بصراحة إذا الشكل ما ينفع يتحوّل بأسلوب اللعبة** بدل ما تجبره.

## ٦) قبل التصدير من Figma (للمصمّم)

- **منظر جانبي فقط، والمركبة متجهة يمين.** لو الرسم متجه يسار اعكسه قبل التصدير.
- **سمّ الطبقات بأسماء تنطبق على وسائط `suv`** — لا أسماء عامة:
  `body` · `glass` · `pillar-b` · `pillar-c` · `door-1..3` · `arch-front` · `arch-rear`
  · `grille` · `headlight` · `taillight` · `rack` · `lightbar` · `snorkel` · `spare` · `mirror`
- **ادمج جسم السيارة في مسار واحد** (`body`)، وخلّي التفاصيل طبقات منفصلة. لو صدّرت
  كل شي مسار واحد مدموج، ما راح يقدر يفصل الهيكل عن الشبك والنوافذ.
- **أضف خطين إرشاديين مسمّيين:** خط أفقي اسمه `ground` عند ملامسة الإطارات للأرض،
  وخط رأسي اسمه `center` عند مركز المركبة. بدونهما ما فيه طريقة دقيقة لمطابقة
  نظام الإحداثيات (`ground` → `y=+45`، `center` → `x=0`).
- **ارسم دائرتين على مركزي العجلتين** مسمّيتين `wheel-front` و`wheel-rear` بنصف القطر
  الحقيقي — منها تُشتق `wf` و`wr` و`r` و`arch`.
- اكتب في الرسالة **نصف الطول `L` المقصود** بالبكسل (٧٢–١١٠) واسم المركبة وسعرها المقترح.
